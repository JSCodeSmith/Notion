Object.hasOwn()

📄 Título

Object.hasOwn()

📝 Definición

Object.hasOwn()

Es un método estático de Object que comprueba si un objeto posee una propiedad propia con un nombre o Symbol determinado.

🧠 ¿Qué es?

Es una forma moderna y segura de preguntar:

"¿Esta propiedad pertenece directamente a este objeto?"
const persona= {
    nombre:"Josué"
};
console.log(Object.hasOwn(persona,"nombre"));// true

Pero si la propiedad viene heredada desde el prototipo:

const persona= {};
console.log(Object.hasOwn(persona,"toString"));// false

toString existe, pero no es una propiedad propia de persona.

🎯 ¿Para qué sirve?

Sirve para:

  • 🔍 Comprobar si una propiedad pertenece directamente a un objeto.
  • 🧬 Distinguir propiedades propias de propiedades heredadas.
  • 🛡️ Evitar problemas al trabajar con objetos que tienen prototipos personalizados.
  • 🧩 Trabajar con objetos dinámicamente.
  • 🔄 Validar propiedades antes de acceder a ellas.

⚙️ ¿Cómo funciona?

Recibe dos argumentos:

Object.hasOwn(obj,prop)

El proceso conceptual es:

objeto
   │
   └── propiedad
          ↓
    Object.hasOwn()
          ↓
       ¿Es propia?
        ↙      ↘
      true     false

Ejemplo:

const usuario= {
    nombre:"Josué"
};
Object.hasOwn(usuario,"nombre");// true

La propiedad está directamente dentro de usuario.

📝 Sintaxis / Estructura

Object.hasOwn(obj,prop)

Parámetros

obj

El objeto que quieres comprobar.

prop

El nombre de la propiedad que quieres comprobar.

Puede ser una cadena o un Symbol.

Object.hasOwn(usuario,"nombre");

Retorno

Devuelve un valor booleano:

true  → la propiedad es propia del objeto
false → la propiedad no es propia del objeto

💡 Ejemplos

1. Propiedad propia

const persona= {
    nombre:"Josué"
};
console.log(Object.hasOwn(persona,"nombre"));// true

2. Propiedad inexistente

const persona= {
    nombre:"Josué"
};
console.log(Object.hasOwn(persona,"edad"));// false

3. Propiedad heredada

const persona= {};
console.log(Object.hasOwn(persona,"toString"));// false

Aunque:

console.log(persona.toString);// existe

toString se encuentra en la cadena de prototipos, no directamente en persona.

persona
   │
   └── [[Prototype]]
          ↓
     Object.prototype
          │
          └── toString

Por eso:

Object.hasOwn(persona,"toString");// false

4. Diferencia con in

Esta diferencia es muy importante:

const persona= {};
console.log("toString"inpersona);// true

in busca en:

objeto + cadena de prototipos

Mientras:

Object.hasOwn(persona,"toString");// false

solo comprueba:

objeto

Comparación:

"prop" in objeto
       ↓
¿Existe en el objeto O en su prototipo?

Object.hasOwn(objeto, "prop")
       ↓
¿Existe directamente en el objeto?

5. Propiedades con Symbol

También funciona con Symbol:

const id=Symbol("id");
const usuario= {
    [id]:123
};
console.log(Object.hasOwn(usuario,id));// true

⚠️ Errores comunes

1. Confundirlo con in

"toString"in {};// true

Pero:

Object.hasOwn({},"toString");// false

in → objeto + prototipo.

Object.hasOwn() → solamente propiedades propias.

2. Pensar que comprueba si la propiedad tiene un valor

const usuario= {
    nombre:undefined
};
console.log(Object.hasOwn(usuario,"nombre"));// true

Aunque el valor sea undefined, la propiedad sí existe.

Esto es diferente de:

usuario.nombre!==undefined

que daría:

false

3. Usar hasOwnProperty() sin considerar sus limitaciones

Tradicionalmente se utilizaba:

obj.hasOwnProperty("nombre");

Pero esto puede ser problemático si el objeto no tiene hasOwnProperty disponible o si una propiedad lo sobrescribe.

Por ejemplo:

const objeto= {
    hasOwnProperty:"Hola"
};

En cambio:

Object.hasOwn(objeto,"hasOwnProperty");// true

es una forma más directa y robusta.

💼 Casos de uso

  • 🔍 Comprobar propiedades de objetos.
  • 📦 Procesar datos recibidos dinámicamente.
  • 🔄 Recorrer objetos.
  • 🧩 Trabajar con objetos creados mediante Object.create().
  • 🛡️ Validar estructuras de datos.
  • 🛠️ Desarrollo de librerías y utilidades.

Un patrón frecuente:

const configuracion= {
    tema:"oscuro"
};
if (Object.hasOwn(configuracion,"tema")) {
	console.log("La configuración tiene tema");
}

🧠 Analogía

Imagina una casa 🏠 y su familia.

Casa de Josué
├── nombre       ← propiedad propia
└── edad         ← propiedad propia

Casa de los padres
└── apellido     ← propiedad heredada

Object.hasOwn() pregunta:

"¿Esta cosa está dentro de MI casa?"

No pregunta si puedes acceder a ella desde algún lugar de la familia.

Por eso:

Object.hasOwn(persona,"nombre");// true

pero una propiedad heredada:

Object.hasOwn(persona,"toString");// false

📝 Notas Personales

Object.hasOwn() permite comprobar de forma directa si una propiedad pertenece directamente al objeto, sin considerar la cadena de prototipos.

Idea clave:

Object.hasOwn(obj, prop)
            ↓
   ¿prop pertenece directamente
        a obj?
            ↓
       true / false

🔥 Regla mental:

hasOwn() = "¿Es MÍA esta propiedad?"
