height

📄 height

📝 Definición

height es una propiedad CSS que establece la altura de la caja de contenido de un elemento (o del borde, según box-sizing).

🧠 ¿Qué es?

Forma parte de las propiedades de dimensiones (junto con width, min-height, max-height, min-width, max-width).

Define cuánto ocupa verticalmente un elemento.

Por defecto, height se refiere a la altura del contenido, no a la altura total.

Con box-sizing: border-box, incluye padding y border.

No aplica a elementos inline (no reemplazados).

Sí aplica a block, inline-block, flex, grid, table-cell, etc.

🎯 ¿Para qué sirve?

  • Definir la altura de secciones, tarjetas, héroes, modales.
  • Crear layouts de pantalla completa (100vh).
  • Ajustar imágenes, videos, iconos.
  • Controlar la altura de inputs, botones, celdas de tabla.
  • Reservar espacio para evitar CLS (layout shift).
  • Igualar alturas en columnas (aunque flex/grid suelen ser mejores).

⚙️ ¿Cómo funciona?

El navegador calcula la altura según el valor y el box-sizing:

  1. content-box (por defecto) → height = altura del contenido. La altura total = height + padding + border.
  1. border-box → height = altura total (incluye padding y border).
  1. auto → el navegador calcula la altura según el contenido (por defecto).
  1. Porcentaje → relativo a la altura del contenedor. ⚠️ Requiere que el padre tenga altura definida, o no funciona.
  1. min-height / max-height → sobrescriben height si el valor calculado se sale del rango.
  1. En flex → align-items: stretch (por defecto) estira los ítems a la altura del contenedor.
  1. En grid → align-items: stretch (por defecto) estira los ítems a la altura de la fila.

📝 Sintaxis / Estructura

selector {
  height: valor;
}

Unidades de viewport

UnidadDescripción
vh1% del viewport grande (incluye barras móviles).
svh1% del viewport pequeño (barras visibles).
lvh1% del viewport grande (barras ocultas).
dvh1% del viewport dinámico (cambia con las barras).

Recomendación moderna: usar dvh o svh en lugar de vh para móviles.

Propiedades relacionadas

min-height: 100vh;
max-height: 80vh;
height: clamp(400px, 60vh, 800px);
aspect-ratio: 16 / 9; /* altura derivada del ancho */

💡 Ejemplos

/* 1. Sección a pantalla completa */
.hero {
  height: 100vh;
}
.hero-moderno {
  height: 100dvh; /* mejor en móviles */
}

/* 2. Altura fija */
.header {
  height: 64px;
}

/* 3. Input cómodo */
input {
  height: 44px; /* mínimo táctil accesible */
}

/* 4. Imagen responsive */
img {
  width: 100%;
  height: auto;
}

/* 5. Min-height para crecer con el contenido */
.main {
  min-height: 100vh;
}

/* 6. Modal centrado */
.modal {
  height: 80vh;
  max-height: 600px;
  overflow-y: auto;
}

/* 7. Aspect ratio sin fijar height */
.video {
  width: 100%;
  aspect-ratio: 16 / 9;
}

/* 8. Altura fluida */
.banner {
  height: clamp(300px, 50vh, 600px);
}

/* 9. Celdas de tabla con altura mínima */
td {
  height: 48px;
}

/* 10. Flex con altura igualada */
.row {
  display: flex;
  align-items: stretch; /* por defecto */
}
.col {
  flex: 1;
  /* los hijos se estiran a la misma altura */
}

Diferencia entre content-box y border-box

/* content-box (por defecto) */
.caja-a {
  box-sizing: content-box;
  height: 200px;
  padding: 20px;
  border: 5px solid;
  /* altura total = 200 + 40 + 10 = 250px ⚠️ */
}

/* border-box (recomendado) */
.caja-b {
  box-sizing: border-box;
  height: 200px;
  padding: 20px;
  border: 5px solid;
  /* altura total = 200px ✅ */
}

Diferencia entre vh, svh, lvh y dvh

/* En móvil con barra de navegación dinámica */
.hero-vh   { height: 100vh; }   /* puede causar overflow */
.hero-svh  { height: 100svh; }  /* siempre cabe, con barras visibles */
.hero-lvh  { height: 100lvh; }  /* altura máxima, con barras ocultas */
.hero-dvh  { height: 100dvh; }  /* se adapta dinámicamente ✅ */

Porcentaje: el error clásico

/* ❌ NO funciona: el padre no tiene altura definida */
.padre {
  /* sin height */
}
.hijo {
  height: 50%; /* → auto, no 50% */
}

/* ✅ SÍ funciona */
.padre {
  height: 400px;
}
.hijo {
  height: 50%; /* → 200px */
}

/* ✅ Alternativa moderna: usar flex/grid */
.padre {
  display: flex;
  height: 400px;
}
.hijo {
  flex: 0 0 50%;
}

⚠️ Errores comunes

  1. Usar % sin padre con altura definida → el hijo ignora el % y cae a auto. Usar flex, grid o vh.
  1. Fijar height en texto → si el contenido crece (más texto, fuente más grande), se desborda. Usar min-height en su lugar.
  1. height: 100vh en móviles → las barras del navegador causan overflow. Usar dvh o svh.
  1. Olvidar box-sizing: border-box → padding y border suman a la altura total.
  1. Aplicar height a elementos inline → no tiene efecto. Usar inline-block o block.
  1. Confundir height con line-height → line-height es altura de línea de texto; height es del bloque.
  1. Igualar alturas con height fijo → rompe con contenido variable. Usar flex/grid con stretch.
  1. No usar min-height: 0 en flex → el contenido puede desbordar porque el mínimo por defecto es auto.
  1. Fijar height en imágenes sin object-fit → la imagen se deforma. Usar object-fit: cover o aspect-ratio.
  1. height: 100% en body/html → requiere que html y body tengan height: 100% también. Alternativa: min-height: 100vh en body.

🧩 Relación con otros conceptos

  • width → ancho del elemento.
  • box-sizing → define si height incluye padding y border.
  • min-height / max-height → límites de altura.
  • line-height → altura de línea de texto (no confundir).
  • aspect-ratio → deriva la altura del ancho (o viceversa).
  • vh / dvh / svh → unidades relativas al viewport.
  • overflow → qué hacer si el contenido excede la altura.
  • align-items: stretch → estira ítems flex/grid a la altura del contenedor.
  • object-fit → cómo ajustar imágenes/videos dentro de una altura fija.
  • calc() → mezcla unidades para calcular alturas.
  • clamp() → altura fluida con límites.
  • CLS → reservar height evita saltos de layout.

🧠 Analogía

Imagina que cada elemento es una caja de cartón. El height es la altura de la caja. Si la fijas y metes más cosas de las que caben, la caja se desborda (overflow). Si usas min-height, la caja empieza con esa altura mínima pero crece si hace falta. Y si usas height: 100vh, es como decir "quiero una caja que ocupe toda la estantería" → pero ojo, la estantería (el viewport) puede cambiar en móvil (barras del navegador) → por eso dvh es más fiable.

📝 Notas personales

  • Siempre box-sizing: border-box → evita sumar padding y border a la altura total.
  • % requiere padre con altura → si no, el hijo cae a auto. Preferir flex/grid o vh/dvh.
  • height: 100vh en móviles → usar 100dvh o 100svh para evitar overflow por las barras.
  • Para que crezca con el contenido → usar min-height, no height.
  • Footer al fondo → body { min-height: 100dvh; display: flex; flex-direction: column } + main { flex: 1 }.
  • Imágenes: width: 100%; height: auto → responsive sin deformar; o aspect-ratio + object-fit: cover.
  • Igualar alturas → flex/grid con stretch (por defecto), no height fijo.
  • min-height: 0 en flex → evita desbordes porque el mínimo por defecto es auto.
  • Accesibilidad táctil → inputs y botones con min-height: 44px (recomendación WCAG).
  • CLS → reservar height o aspect-ratio en imágenes/videos evita saltos de layout.
  • aspect-ratio → moderna y preferible a fijar height cuando quieres mantener proporción.
