margin

📄 margin

📝 Definición

margin es una propiedad CSS de la caja (box model) que define el espacio exterior alrededor de un elemento, es decir, la distancia entre el borde del elemento y los elementos adyacentes.

🧠 ¿Qué es?

Forma parte del modelo de caja (box model) junto con padding, border y content.

Es el espacio fuera del borde, que empuja a otros elementos lejos del nuestro.

A diferencia de padding, margin no tiene fondo ni color propio: es puro espacio transparente.

Y a diferencia de otros espaciados, participa en el colapso de márgenes (margin collapsing).

🎯 ¿Para qué sirve?

  • Separar elementos entre sí (vertical u horizontalmente).
  • Centrar bloques horizontalmente (margin: 0 auto).
  • Crear ritmo vertical en tipografía y secciones.
  • Empujar elementos dentro de un contenedor flex/grid.
  • Controlar el espaciado en layouts sin padding.

⚙️ ¿Cómo funciona?

Cada elemento de bloque tiene 4 márgenes: top, right, bottom, left.

Se aplican fuera del borde y afectan a la posición del elemento y de los vecinos.

Conceptos clave:

  1. Colapso de márgenes (margin collapsing) → márgenes verticales adyacentes entre bloques se fusionan, quedando el mayor de los dos (no la suma).
  1. Márgenes negativos → permitidos; pueden solapar elementos o "tirar" de ellos.
  1. margin: auto → en bloques con width definido, centra horizontalmente.
  1. No aplica en elementos inline → los márgenes verticales no afectan a display: inline; sí los horizontales.
  1. En flex/grid → no hay colapso de márgenes; se respetan tal cual.

📝 Sintaxis / Estructura

/* Un valor: todos los lados */
margin: 10px;

/* Dos valores: vertical | horizontal */
margin: 10px 20px;

/* Tres valores: top | horizontal | bottom */
margin: 10px 20px 30px;

/* Cuatro valores: top | right | bottom | left (sentido horario) */
margin: 10px 20px 30px 40px;

Propiedades individuales

margin-top: 10px;
margin-right: 20px;
margin-bottom: 30px;
margin-left: 40px;

Propiedades lógicas (modernas)

margin-block: 10px 20px;   /* top | bottom (según writing-mode) */
margin-inline: 20px 30px;  /* left | right (según writing-mode) */
margin-block-start: 10px;
margin-inline-end: 20px;

💡 Ejemplos

/* 1. Separación básica */
.card {
  margin: 16px;
}

/* 2. Centrar horizontalmente */
.container {
  width: 800px;
  margin: 0 auto;
}

/* 3. Espaciado vertical entre párrafos */
p {
  margin: 0 0 1em 0;
}

/* 4. Márgenes individuales */
.btn {
  margin-top: 8px;
  margin-left: 4px;
}

/* 5. Margen negativo para solapar */
.avatar {
  margin-left: -12px;
}

/* 6. Propiedades lógicas */
.box {
  margin-block: 1rem;
  margin-inline: 2rem;
}

/* 7. Reset universal (muy común) */
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}

Ejemplo de colapso de márgenes

<div class="a">A</div>
<div class="b">B</div>
.a { margin-bottom: 40px; }
.b { margin-top: 20px; }

Resultado: la separación entre A y B es 40px, no 60px. Los márgenes colapsan.

⚠️ Errores comunes

  1. No entender el colapso de márgenes → dos bloques con margin-bottom: 30px y margin-top: 20px no suman 50px, sino que quedan 30px.
  1. Esperar que margin: auto centre verticalmente → solo centra horizontal en bloques. Para vertical, usar flex/grid o position: absolute.
  1. Usar margin-top en hijos de un padre sin padding/border → el margen "se escapa" del padre (margin collapsing). Solución: padding, border, overflow: hidden, o display: flow-root.
  1. Confundir % en top/bottom → el porcentaje siempre se calcula respecto al ancho del contenedor, no a la altura.
  1. Aplicar márgenes verticales a display: inline → no tienen efecto. Usar inline-block o block.
  1. Olvidar resetear márgenes por defecto → navegadores aplican márgenes a body, p, h1, etc.
  1. Usar margen para separar en flex/grid sin control → en flex/grid conviene gap en lugar de márgenes para espaciado uniforme.
  1. Abusar de márgenes negativos → funcionan, pero complican el mantenimiento y el responsive.

🧩 Relación con otros conceptos

  • padding → espacio interior (dentro del borde).
  • border → línea entre padding y margin.
  • box-sizing → border-box incluye padding y border en el width, no margin.
  • gap → alternativa moderna a márgenes en flex/grid.
  • outline → no ocupa espacio, a diferencia de border.
  • position: absolute → auto en márgenes tiene comportamiento especial para centrar.
  • Margin collapsing → solo ocurre en bloques en el mismo flujo normal.
  • display: flow-root → evita que los márgenes de los hijos escapen del padre.
  • margin-trim → propiedad experimental que elimina márgenes sobrantes en contenedores.

🧠 Analogía

Imagina que cada elemento es una casa en una urbanización. El margin es el jardín exterior que rodea la parcela: es el espacio que separa tu casa de las casas vecinas. No tiene vallas ni nada, es simplemente terreno vacío que impide que las casas se toquen. Si dos casas tienen jardines grandes, el espacio entre ellas será el del jardín más grande, no la suma (eso es el colapso de márgenes).

📝 Notas personales

  • Regla mental: margin = espacio fuera; padding = espacio dentro.
  • El colapso de márgenes es la causa nº1 de bugs raros con espaciados verticales.
  • Para evitar colapso indeseado en el padre: padding, border, overflow: hidden o display: flow-root.
  • En flex y grid, no hay colapso y gap es preferible a márgenes.
  • margin: 0 auto centra horizontalmente, pero requiere width definido y display: block.
  • Los márgenes negativos son potentes pero peligrosos: usarlos con criterio.
  • En proyectos modernos, resetear márgenes con { margin: 0 } o usar un reset más fino (como el de Andy Bell) es casi obligatorio.
  • Los porcentajes en margin-top/bottom se calculan sobre el ancho del contenedor → útil para aspect ratios.
  • Preferir propiedades lógicas (margin-inline, margin-block) para soportar i18n y RTL/LTR.
