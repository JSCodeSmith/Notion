box-sizing

📄 box-sizing

📝 Definición

box-sizing es una propiedad CSS que define cómo se calculan el ancho y la altura de un elemento: si width/height incluyen el padding y el border (border-box) o solo el contenido (content-box).

🧠 ¿Qué es?

Forma parte del modelo de caja (box model) y es una de las propiedades más importantes para el desarrollo web moderno.

Cambia la forma en que el navegador interpreta width y height, y por tanto, cómo se comportan los layouts.

Es la propiedad que soluciona el problema clásico de "puse width: 100% y se desborda porque le añadí padding".

🎯 ¿Para qué sirve?

  • Evitar que el padding y el border agranden el elemento.
  • Hacer layouts predecibles sin cálculos mentales.
  • Facilitar el responsive (width: 100% sin sustos).
  • Simplificar el uso de grids y flexbox.
  • Crear componentes con anchos exactos.
  • Estandarizar el comportamiento entre navegadores.
  • Combinar con border-box para que width sea el ancho total.

⚙️ ¿Cómo funciona?

El navegador calcula el ancho/alto total según el valor:

  1. content-box (por defecto) → width/height = solo el contenido. El ancho total = width + padding + border.
  1. border-box → width/height = contenido + padding + border. El ancho total = width.

Reglas clave:

  • content-box es el valor inicial → definido por el estándar CSS original.
  • border-box es lo que casi todo el mundo quiere → más intuitivo.
  • border-box no incluye el margin → el margin siempre está fuera.
  • Se puede aplicar a → el reset más famoso de la historia de CSS.
  • Se hereda → con inherit se puede propagar.
  • Afecta a width, height, min-*, max-* → todas las propiedades de tamaño.
  • No afecta a margin → el margin siempre suma fuera.
  • En flex/grid → border-box es especialmente útil porque los ítems suelen tener padding.

📝 Sintaxis / Estructura

selector {
  box-sizing: valor;
}

💡 Ejemplos

/* 1. Reset universal (el más famoso) */
*, *::before, *::after {
  box-sizing: border-box;
}

/* 2. Contenedor responsive sin sustos */
.container {
  box-sizing: border-box;
  width: 100%;
  padding: 20px;
  border: 2px solid #333;
  /* Ancho total = 100% ✅ */
}

/* 3. Input con padding */
input {
  box-sizing: border-box;
  width: 300px;
  padding: 12px;
  border: 1px solid #ccc;
  /* Ancho total = 300px ✅ */
}

/* 4. Grid con gap y padding */
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
.card {
  box-sizing: border-box;
  padding: 20px;
  border: 1px solid #ddd;
  /* Ancho total = 1fr ✅ */
}

/* 5. Columna al 50% con padding */
.col {
  box-sizing: border-box;
  width: 50%;
  padding: 20px;
  /* Ancho total = 50% ✅ (con content-box sería 50% + 40px) */
}

/* 6. Sin border-box (comportamiento clásico) */
.clasico {
  box-sizing: content-box;
  width: 300px;
  padding: 20px;
  border: 5px solid #333;
  /* Ancho total = 300 + 40 + 10 = 350px ⚠️ */
}

/* 7. Con border-box */
.moderno {
  box-sizing: border-box;
  width: 300px;
  padding: 20px;
  border: 5px solid #333;
  /* Ancho total = 300px ✅ */
}

/* 8. Herencia controlada */
.padre {
  box-sizing: border-box;
}
.hijo {
  box-sizing: inherit;
  /* Hereda border-box del padre */
}

/* 9. Reset moderno (más limpio) */
html {
  box-sizing: border-box;
}
*, *::before, *::after {
  box-sizing: inherit;
}

/* 10. Solo en un componente específico */
.card {
  box-sizing: border-box;
}

El reset universal (patrón más usado)

*, *::before, *::after {
  box-sizing: border-box;
}

Reset moderno con herencia controlada

html {
  box-sizing: border-box;
}
*, *::before, *::after {
  box-sizing: inherit;
}
/* Permite cambiar box-sizing en un componente y que sus hijos lo hereden */

Diferencia visual

/* content-box (por defecto) */
.caja-a {
  box-sizing: content-box;
  width: 300px;
  padding: 20px;
  border: 5px solid #333;
  /* Ancho total = 300 + 20 + 20 + 5 + 5 = 350px */
}

/* border-box */
.caja-b {
  box-sizing: border-box;
  width: 300px;
  padding: 20px;
  border: 5px solid #333;
  /* Ancho total = 300px (padding y border incluidos) */
  /* Contenido = 300 - 20 - 20 - 5 - 5 = 250px */
}

Impacto en layouts

/* Sin border-box: se desborda */
.col-50 {
  width: 50%;
  padding: 20px;
  /* Ancho total = 50% + 40px → se desborda ⚠️ */
}

/* Con border-box: perfecto */
.col-50 {
  box-sizing: border-box;
  width: 50%;
  padding: 20px;
  /* Ancho total = 50% ✅ */
}

Input con padding

/* Sin border-box */
input {
  width: 100%;
  padding: 12px;
  border: 1px solid #ccc;
  /* Ancho total = 100% + 24px + 2px → se desborda del contenedor ⚠️ */
}

/* Con border-box */
input {
  box-sizing: border-box;
  width: 100%;
  padding: 12px;
  border: 1px solid #ccc;
  /* Ancho total = 100% ✅ */
}

⚠️ Errores comunes

  1. No usar box-sizing: border-box → el padding y el border agrandan el elemento y rompen layouts. El error nº1 de CSS.
  1. Confundir content-box con border-box → content-box es el valor por defecto (y suele ser el problema); border-box es el que quieres.
  1. Pensar que border-box incluye el margin → no, el margin siempre está fuera del ancho/alto.
  1. Aplicarlo solo a algunos elementos → si no es universal, se producen inconsistencias. Usar el reset universal.
  1. Olvidar ::before y ::after → los pseudo-elementos también necesitan border-box si tienen padding/border.
  1. Esperar que cambie el tamaño visual → box-sizing cambia cómo se interpreta width, no el tamaño en sí.
  1. Usarlo con flex/grid sin reset → los ítems con padding se desbordan. border-box es esencial.
  1. Confundir con box-shadow → box-sizing afecta al tamaño; box-shadow es puramente visual y no afecta al layout.
  1. No usarlo en inputs → los inputs con width: 100% y padding se desbordan. border-box es imprescindible.
  1. Pensar que border-box es "más moderno" → es de CSS3, pero hoy es el estándar de facto.
  1. Resetear con { box-sizing: border-box } sin ::before/::after → los pseudo-elementos quedan fuera.
  1. Usar inherit sin definir border-box en el padre → el hijo hereda content-box (el valor por defecto).

🧩 Relación con otros conceptos

  • width → interpretado según box-sizing.
  • height → interpretado según box-sizing.
  • padding → suma al ancho en content-box; incluido en border-box.
  • border → suma al ancho en content-box; incluido en border-box.
  • margin → nunca incluido en box-sizing.
  • min-width / max-width → también afectados.
  • box-shadow → no afecta al layout; no lo incluye box-sizing.
  • outline → no afecta al layout; no lo incluye box-sizing.
  • flex-basis → en flex, border-box afecta a cómo se calcula.
  • grid → border-box es esencial para ítems con padding.
  • display → border-box funciona igual en todos los displays.

🧠 Analogía

Imagina que cada elemento es una caja de cartón:

  • content-box → mides solo el interior (donde va el objeto). El cartón (padding + border) se suma aparte. Si pides una caja de 300px, el cartón la agranda a 350px.
  • border-box → mides la caja entera, incluyendo el cartón. Si pides 300px, tienes 300px totales, y el interior es más pequeño.

Por eso border-box es más intuitivo: pides 300px y obtienes 300px, sin sorpresas.

📝 Notas personales

  • Regla de oro: , *::before, *::after { box-sizing: border-box } → el reset más útil de la historia de CSS.
  • content-box es el valor por defecto → y suele ser el problema, no la solución.
  • border-box no incluye margin → el margin siempre está fuera del ancho/alto.
  • Reset moderno → html { box-sizing: border-box } *, *::before, *::after { box-sizing: inherit } permite cambiar box-sizing en componentes aislados.
  • Imprescindible en inputs → sin border-box, width: 100% + padding se desborda.
  • Esencial en flex/grid → los ítems con padding se desbordan sin border-box.
  • No afecta a box-shadow ni outline → son visuales y no suman al layout.
  • margin siempre fuera → no importa el box-sizing; el margin nunca se incluye.
  • Hoy es el estándar → prácticamente todos los proyectos modernos lo usan. No usarlo es la excepción.
