:first-child

📄 :first-child

📝 Definición

:first-child es una pseudo-clase estructural de CSS que selecciona un elemento solo si es el primer hijo de su elemento padre.

🧠 ¿Qué es?

Forma parte de las pseudo-clases estructurales (junto con :last-child, :nth-child(), :only-child, etc.).

No depende de la interacción del usuario, sino de la posición del elemento dentro del árbol DOM.

Importante: se basa en la posición entre hermanos, no en el tipo de elemento.

Si el primer hijo es un <p> y aplicas div:first-child, no coincidirá salvo que ese <p> sea un div.

🎯 ¿Para qué sirve?

  • Aplicar estilos solo al primer elemento de una lista, contenedor o grupo.
  • Eliminar márgenes/bordes del primer ítem sin usar clases extra.
  • Crear diseños tipo "grid" o "listas" con separadores entre elementos.
  • Evitar añadir clases como .first en HTML.

⚙️ ¿Cómo funciona?

El navegador evalúa la posición del elemento dentro de su padre:

  1. Toma el elemento al que apunta el selector.
  1. Verifica si es el primer hijo de su padre (contando cualquier tipo de nodo elemento).
  1. Si lo es, aplica los estilos.

⚠️ No cuenta nodos de texto ni comentarios, solo elementos. Pero sí cuenta elementos de cualquier tipo, no solo del mismo tag.

📝 Sintaxis / Estructura

selector:first-child {
  propiedad: valor;
}

Variantes relacionadas

:first-child        /* primer hijo de cualquier tipo */
:first-of-type      /* primer hijo de su mismo tipo */
:nth-child(1)       /* equivalente a :first-child */

💡 Ejemplos

/* 1. Primer párrafo de un artículo */
article p:first-child {
  font-weight: bold;
  font-size: 1.2em;
}

/* 2. Quitar margen superior al primer hijo */
.card > *:first-child {
  margin-top: 0;
}

/* 3. Primer ítem de una lista */
ul li:first-child {
  border-top: none;
}

/* 4. Diferencia con :first-of-type */
div p:first-child {
  color: red;   /* solo si el <p> es el PRIMER hijo del div */
}
div p:first-of-type {
  color: blue;  /* el primer <p> aunque no sea el primer hijo */
}

Ejemplo comparativo clave

<div>
  <h1>Título</h1>
  <p>Párrafo 1</p>
  <p>Párrafo 2</p>
</div>
div p:first-child    { color: red; }   /* ❌ NO aplica: <p> no es primer hijo */
div p:first-of-type  { color: blue; }  /* ✅ Aplica al <p>Párrafo 1</p> */

⚠️ Errores comunes

  1. Confundir :first-child con :first-of-type → el más habitual. :first-child exige ser el primer hijo absoluto; :first-of-type solo exige ser el primero de su tipo.
  1. Ignorar nodos previos → un <span> o comentario antes rompe el :first-child del <p>.
  1. Olvidar el contexto del padre → p:first-child requiere que ese <p> sea hijo directo del mismo padre.
  1. Usarlo dentro de :not() mal escrito → :not(:first-child) es válido y muy útil; olvidar los dos puntos rompe todo.
  1. Esperar que cuente texto → los nodos de texto no cuentan como hijos para esta pseudo-clase.
  1. Problemas con display: none → los elementos ocultos sí cuentan en la posición, salvo que se eliminen del DOM.

🧩 Relación con otros conceptos

  • :last-child → el último hijo.
  • :only-child → el único hijo.
  • :nth-child(n) → posición específica.
  • :first-of-type → primero de su tipo (no confundir).
  • :not(:first-child) → todos menos el primero (muy usado).
  • :has() → permite condicionar según descendientes.
  • Combinadores > y + → + (hermano adyacente) suele combinarse para separadores.

Combinación típica:

li + li { border-top: 1px solid #ddd; }

Esto es una alternativa a :not(:first-child).

🧠 Analogía

Imagina una fila de personas esperando el autobús. :first-child señala únicamente a la primera persona de la fila, sin importar quién sea (niño, adulto, anciano). En cambio, :first-of-type señalaría "el primer niño de la fila", aunque no esté primero.

📝 Notas personales

  • La regla de oro: :first-child = posición absoluta; :first-of-type = posición relativa al tipo.
  • Si algo no funciona, inspecciona el DOM: probablemente hay un nodo anterior (incluso un <script> o <template>).
  • :not(:first-child) es más limpio que añadir clases .not-first en HTML.
  • Para listas con separadores, li + li suele ser más elegante y compatible que :not(:first-child).
  • No confundir con :first-line o ::first-letter, que son pseudo-elementos, no pseudo-clases.
  • Los elementos con display: none siguen contando en la posición → cuidado con menús colapsados.
