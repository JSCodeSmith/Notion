display

📄 display

📝 Definición

display es una propiedad CSS que define cómo se comporta un elemento en el flujo del documento: si genera una caja de bloque, en línea, flex, grid, tabla, etc., y cómo se comportan sus hijos.

🧠 ¿Qué es?

Es una de las propiedades más importantes y fundamentales de CSS.

Determina el tipo de caja que genera un elemento y, por tanto, cómo se posiciona, cómo se dimensiona y cómo se relaciona con los elementos vecinos.

display es un shorthand moderno que puede definir dos cosas a la vez:

  • Tipo de display exterior → cómo se comporta el elemento hacia fuera (block, inline).
  • Tipo de display interior → cómo se organizan sus hijos (flow, flex, grid).

🎯 ¿Para qué sirve?

  • Definir si un elemento es bloque o en línea.
  • Activar flexbox o grid para layouts modernos.
  • Ocultar elementos (display: none).
  • Cambiar el comportamiento de elementos HTML (ej. <a> como bloque).
  • Crear tablas con CSS sin usar <table>.
  • Controlar el flujo de contenido interno.
  • Construir layouts complejos sin modificar el HTML.

⚙️ ¿Cómo funciona?

El navegador asigna un tipo de caja según el valor de display.

Este tipo afecta a:

  1. Cómo se posiciona → bloque (nueva línea) o inline (en la misma línea).
  1. Cómo se dimensiona → bloque (ocupa el 100% del padre), inline (se ajusta al contenido).
  1. Cómo se organizan sus hijos → flujo normal, flex, grid, tabla.
  1. Si aparece en el árbol de accesibilidad → none lo elimina; contents lo disuelve.

📝 Sintaxis / Estructura

selector {
  display: valor;
}

Valores modernos (shorthand de 2 valores)

display: inline flex;   /* inline por fuera, flex por dentro */
display: block grid;    /* block por fuera, grid por dentro */
display: block flow;    /* equivale a block */
display: inline flow;   /* equivale a inline */
display: block flow-root; /* equivale a flow-root */

💡 Ejemplos

/* 1. Bloque vs en línea */
div {
  display: block;      /* ocupa todo el ancho, nueva línea */
}
span {
  display: inline;     /* en la misma línea, se ajusta al contenido */
}

/* 2. Enlace como botón de bloque */
a.btn {
  display: block;
  padding: 12px 24px;
  background: #3498db;
  color: white;
  text-align: center;
}

/* 3. Enlace como bloque en línea */
a.btn-inline {
  display: inline-block;
  padding: 8px 16px;
  background: #3498db;
  color: white;
}

/* 4. Ocultar elemento */
.oculto {
  display: none;
  /* El elemento desaparece del flujo y del árbol de accesibilidad */
}

/* 5. Flexbox */
.container {
  display: flex;
  justify-content: center;
  align-items: center;
  gap: 16px;
}

/* 6. Grid */
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

/* 7. Layout de tabla sin <table> */
.tabla {
  display: table;
  width: 100%;
}
.fila {
  display: table-row;
}
.celda {
  display: table-cell;
  padding: 8px;
  border: 1px solid #ddd;
}

/* 8. Flow-root: contiene márgenes flotantes */
.contenedor {
  display: flow-root;
  /* Establece un nuevo contexto de formato */
  /* Evita que los márgenes de los hijos escapen */
}

/* 9. Lista con display */
.lista {
  display: list-item;
  list-style: disc inside;
}

/* 10. Contents: el elemento desaparece, los hijos suben */
.wrapper {
  display: contents;
  /* El wrapper no genera caja; sus hijos se comportan como si fueran del padre */
}

/* 11. Shorthand moderno de 2 valores */
.inline-flex {
  display: inline flex;
  /* Equivale a display: inline-flex */
}

block vs inline vs inline-block

.block {
  display: block;
  /* Nueva línea, ocupa 100% del padre, acepta width/height/margin/padding */
}

.inline {
  display: inline;
  /* Misma línea, se ajusta al contenido, NO acepta width/height */
  /* Padding horizontal sí, vertical se dibuja pero no empuja líneas */
}

.inline-block {
  display: inline-block;
  /* Misma línea, se ajusta al contenido, SÍ acepta width/height/margin/padding */
}

Centrar con flexbox

.centrar {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}

Grid responsive sin media queries

.grid-auto {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  gap: 16px;
}

Tabla con CSS (sin <table>)

.tabla {
  display: table;
  width: 100%;
  border-collapse: collapse;
}
.fila {
  display: table-row;
}
.celda {
  display: table-cell;
  padding: 12px;
  border: 1px solid #ddd;
}

display: contents (útil con grid/flex)

/* HTML:
<div class="grid">
  <div class="wrapper">
    <div class="item">A</div>
    <div class="item">B</div>
  </div>
</div>
*/

.grid {
  display: grid;
  grid-template-columns: repeat(2, 1fr);
  gap: 8px;
}
.wrapper {
  display: contents;
  /* El wrapper desaparece; los items se comportan como hijos directos del grid */
}

display: flow-root (contener floats)

.contenedor {
  display: flow-root;
  /* Crea un nuevo contexto de formato de bloque */
  /* Contiene los hijos flotantes y evita que los márgenes escapen */
}

⚠️ Errores comunes

  1. Confundir display: none con visibility: hidden → none elimina el elemento del flujo y del árbol de accesibilidad; hidden lo oculta pero sigue ocupando espacio.
  1. Usar display: none para contenido importante → es invisible para lectores de pantalla. Usar visibility, opacity o sr-only según el caso.
  1. Pensar que inline acepta width/height → no; se ajusta al contenido. Usar inline-block o block.
  1. Aplicar márgenes verticales a inline → no empujan líneas; solo el horizontal afecta al flujo.
  1. Usar display: table para layouts → fue un hack en los 2000; hoy usar flex/grid.
  1. Cambiar display y romper el layout → algunos elementos (ej. <li>) dependen de su display para el marcador.
  1. display: contents en elementos con rol semántico → puede eliminar el rol del elemento en accesibilidad (bug histórico; ya corregido en navegadores modernos).
  1. Animar display → no es animable directamente. Usar @starting-style, opacity, visibility o transition-behavior: allow-discrete.
  1. Usar display: inline-block para todo → no es la solución universal; flex/grid son mejores para layouts.
  1. Confundir display: flex con flex: 1 → uno es el contenedor; el otro es el ítem.
  1. Olvidar que display afecta al árbol de accesibilidad → none lo elimina; contents puede cambiar roles.
  1. Usar !important para sobrescribir display → suele indicar un problema de estructura CSS.

🧩 Relación con otros conceptos

  • position → display y position juntos definen el comportamiento del elemento.
  • float → float cambia el display computado a block.
  • flex → propiedad de los ítems flex; display: flex es del contenedor.
  • grid → propiedad de los ítems grid; display: grid es del contenedor.
  • visibility → oculta pero mantiene el espacio.
  • opacity → oculta visualmente pero mantiene el espacio y la accesibilidad.
  • gap → funciona en flex y grid.
  • align-items / justify-content → dependen del tipo de display.
  • flow-root → crea un contexto de formato de bloque (contiene floats).
  • contents → disuelve el elemento; sus hijos suben al padre.
  • box-sizing → afecta a cómo se calculan los tamaños, independientemente de display.
  • Árbol de accesibilidad → display: none y display: contents lo afectan.

Categorías visualizadas:

Exterior:
  block  → ocupa 100%, nueva línea
  inline → se ajusta al contenido, misma línea

Interior:
  flow       → flujo normal
  flow-root  → flujo + nuevo contexto de formato
  flex       → flexbox
  grid       → grid
  table      → tabla

Especiales:
  none     → eliminado del flujo
  contents → el elemento desaparece, hijos suben

🧠 Analogía

Imagina que cada elemento es una caja en un almacén:

  • block → una caja grande que ocupa toda la estantería (nueva línea).
  • inline → un objeto pequeño que se coloca en la misma estantería junto a otros.
  • inline-block → una caja mediana que se coloca en la estantería pero puede tener tamaño propio.
  • flex → una estantería organizadora que coloca sus cajas en fila o columna.
  • grid → una estantería con cuadrícula que coloca sus cajas en celdas.
  • none → la caja no existe en el almacén.
  • contents → la caja se disuelve y sus objetos se colocan directamente en el estante del padre.

📝 Notas personales

  • display es la propiedad más fundamental de CSS → define el comportamiento del elemento.
  • display: none ≠ visibility: hidden → none elimina del flujo y de accesibilidad; hidden mantiene el espacio.
  • flex y grid son los reyes del layout moderno → olvidar float y display: table para layouts.
  • inline-block es útil para botones y badges → pero flex/grid suelen ser mejores para contenedores.
  • flow-root es el "clearfix" moderno → contiene floats y márgenes sin hacks.
  • contents es útil con grid/flex → permite que un wrapper no interfiera en el layout.
  • display no es animable directamente → usar @starting-style o transiciones con opacity/visibility + transition-behavior: allow-discrete.
  • Reset: en 2025, muchos proyectos usan display: block para imágenes, o normalizan button/input con display: inline-block.
  • Accesibilidad: display: none elimina del árbol de accesibilidad; usar .sr-only (con clip-path o position: absolute) para contenido solo para lectores de pantalla.
  • display: contents y accesibilidad → hubo bugs históricos en navegadores; hoy está corregido, pero verificar en casos concretos.
