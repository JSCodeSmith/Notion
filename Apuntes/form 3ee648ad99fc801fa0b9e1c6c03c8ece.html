<form>

📄 <form>

📝 Definición

<form> 

Es el elemento que representa una sección interactiva de un documento que contiene controles de formulario (inputs, botones, selects, etc.) para que el usuario introduzca y envíe datos a un servidor.

🧠 ¿Qué es?

Es un elemento de bloque y semántico que agrupa controles interactivos y define cómo y a dónde se envían los datos.

Sin <form>, los controles existen pero no se pueden enviar de forma nativa.

🎯 ¿Para qué sirve?

  • Recoger datos del usuario (login, registro, contacto).
  • Enviar datos a un servidor (GET o POST).
  • Validar entradas de forma nativa (con atributos HTML5).
  • Agrupar controles relacionados.
  • Mejorar accesibilidad: los lectores de pantalla asocian etiquetas y controles.
  • Aportar semántica: indica que es una zona interactiva.

⚙️ ¿Cómo funciona?

  1. El navegador renderiza un bloque sin estilos visuales por defecto.
  1. Al enviar (submit), el navegador serializa los controles con name y los envía a action con method.
  1. Si no hay action, se envía a la URL actual.
  1. Si no hay method, se usa GET por defecto.
  1. La validación nativa se ejecuta antes del envío (con required, pattern, type, etc.).
  1. Los eventos (submit, reset, input, change) permiten interceptar con JS.

📝 Sintaxis / Estructura

<form action="/enviar" method="post">
  <label for="nombre">Nombre:</label>
  <input type="text" id="nombre" name="nombre" required>
  <button type="submit">Enviar</button>
</form>

💡 Ejemplos

Formulario de contacto:

<form action="/contacto" method="post">
  <label for="nombre">Nombre:</label>
  <input type="text" id="nombre" name="nombre" required>

  <label for="email">Correo:</label>
  <input type="email" id="email" name="email" required>

  <label for="mensaje">Mensaje:</label>
  <textarea id="mensaje" name="mensaje" rows="4"></textarea>

  <button type="submit">Enviar</button>
</form>

Login:

<form action="/login" method="post">
  <label for="usuario">Usuario:</label>
  <input type="text" id="usuario" name="usuario" autocomplete="username" required>

  <label for="password">Contraseña:</label>
  <input type="password" id="password" name="password" autocomplete="current-password" required>

  <button type="submit">Iniciar sesión</button>
</form>

Subida de archivos (con enctype):

<form action="/subir" method="post" enctype="multipart/form-data">
  <label for="archivo">Archivo:</label>
  <input type="file" id="archivo" name="archivo" accept="image/*">
  <button type="submit">Subir</button>
</form>

Con validación nativa:

<form action="/registro" method="post">
  <label for="email">Correo:</label>
  <input type="email" id="email" name="email" required>

  <label for="edad">Edad:</label>
  <input type="number" id="edad" name="edad" min="18" max="120" required>

  <label for="cp">Código postal:</label>
  <input type="text" id="cp" name="cp" pattern="[0-9]{5}" title="5 dígitos">

  <button type="submit">Registrarse</button>
</form>

Con fieldset y legend:

<form action="/pedido" method="post">
  <fieldset>
    <legend>Datos de envío</legend>
    <label for="calle">Calle:</label>
    <input type="text" id="calle" name="calle" required>
  </fieldset>

  <fieldset>
    <legend>Pago</legend>
    <label for="tarjeta">Tarjeta:</label>
    <input type="text" id="tarjeta" name="tarjeta" required>
  </fieldset>

  <button type="submit">Confirmar pedido</button>
</form>

⚠️ Errores comunes

  • ❌ Olvidar name en los controles → no se envían datos.
  • ❌ Olvidar label asociado con for → problema de accesibilidad.
  • ❌ Usar GET para datos sensibles (contraseñas, tarjetas) → van en la URL.
  • ❌ Usar POST sin CSRF protection en el servidor.
  • ❌ Olvidar enctype="multipart/form-data" al subir archivos.
  • ❌ No validar en el servidor (la validación nativa es solo del cliente).
  • ❌ Usar <div> en lugar de <fieldset> para agrupar.
  • ❌ Anidar <form> dentro de otro <form> (inválido).
  • ❌ No incluir autocomplete en campos de login/registro.
  • ❌ Usar <button> sin type → por defecto es submit (puede causar envíos accidentales).

💼 Casos de uso

  • Login y registro de usuarios.
  • Formularios de contacto.
  • Búsqueda en el sitio.
  • Checkout en e-commerce.
  • Suscripción a newsletter.
  • Encuestas y cuestionarios.
  • Reserva de citas o vuelos.
  • Subida de archivos.
  • Configuración de perfil.

🧩 Relación con otros conceptos

  • <input>: control principal (text, email, password, etc.).
  • <label>: etiqueta asociada al control (accesibilidad).
  • <textarea>: texto multilínea.
  • <select> / <option>: listas desplegables.
  • <button>: botones (submit, reset, button).
  • <fieldset> / <legend>: agrupar controles.
  • <output>: resultado de un cálculo.
  • <datalist>: sugerencias para un input.
  • Validación nativa: required, pattern, min, max, type.
  • GET vs POST: método de envío.
  • enctype: codificación del envío (archivos → multipart).
  • CSRF: protección en el servidor.
  • Accesibilidad: label, fieldset, aria-*.

🧠 Analogía

Un <form> es como un formulario en papel que rellenas y entregas en una oficina: tiene campos (inputs), etiquetas (labels), secciones (fieldsets) y un botón de "entregar" (submit). Sin el formulario, los campos sueltos no sirven para nada.

📝 Notas personales

  • Siempre name en los controles: sin él, no se envían.
  • Siempre label asociado con for → accesibilidad.
  • GET para búsquedas; POST para datos sensibles.
  • enctype="multipart/form-data" al subir archivos.
  • Valida en el servidor también: la validación nativa es solo del cliente.
  • autocomplete mejora la experiencia en login/registro.
  • fieldset + legend para agrupar controles relacionados.
  • <button type="submit"> explícito para evitar envíos accidentales.
  • CSRF: el servidor debe protegerse contra ataques.
  • No anides <form>: es inválido y confunde.
  • Buena práctica: usa validación nativa + validación del servidor.
