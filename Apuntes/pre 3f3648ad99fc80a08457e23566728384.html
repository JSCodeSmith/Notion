<pre>

📄 <pre>

📝 Definición

<pre> (del inglés preformatted text, "texto preformateado") es el elemento que representa texto preformateado: conserva exactamente los espacios, tabulaciones y saltos de línea tal como se escriben en el código fuente.

🧠 ¿Qué es?

Es un elemento de bloque y semántico.

Por defecto se renderiza con fuente monoespaciada y respeta el formato original.

Se usa para bloques de código, ASCII art, poemas, tablas de texto, etc.

🎯 ¿Para qué sirve?

  • Mostrar bloques de código con formato.
  • Preservar espacios y saltos de línea.
  • Mostrar ASCII art o diagramas de texto.
  • Poemas o textos con formato específico.
  • Salida de programas o logs.
  • Tablas de texto alineadas con espacios.
  • Combinarse con <code> para código fuente.

⚙️ ¿Cómo funciona?

  1. El navegador lo renderiza como bloque con font-family: monospace y white-space: pre.
  1. Conserva espacios múltiples, tabulaciones y saltos de línea.
  1. No colapsa los espacios (a diferencia del resto del HTML).
  1. No ajusta el texto al ancho del contenedor (puede desbordar).
  1. Se puede combinar con <code> para marcar código.
  1. Los lectores de pantalla lo anuncian como "texto preformateado".

📝 Sintaxis / Estructura

<pre>
Texto   con    espacios
y saltos de línea
conservados.
</pre>

💡 Ejemplos

Bloque de código:

<pre><code>
function saludar(nombre) {
  return `Hola, ${nombre}`;
}
</code></pre>

ASCII art:

<pre>
  /\_/\
 ( o.o )
  > ^ <
</pre>

Poema:

<pre>
Volverán las oscuras golondrinas
en tu balcón sus nidos a colgar,
y otra vez con el ala a sus cristales
jugando llamarán.
</pre>

Tabla de texto alineada:

<pre>
Nombre       Edad    Ciudad
Ana Pérez    28      Madrid
Luis Gómez   34      Buenos Aires
Marta Ruiz   41      Ciudad de México
</pre>

Salida de programa:

<pre>
$ npm install
added 150 packages in 3.2s
$ npm run build
Build completed successfully.
</pre>

Con <code> y resaltado:

<pre><code class="language-javascript">
const numeros = [1, 2, 3];
const dobles = numeros.map(n => n * 2);
console.log(dobles); // [2, 4, 6]
</code></pre>

Con estilos CSS:

<pre class="codigo">
function sumar(a, b) {
  return a + b;
}
</pre>
pre.codigo {

Con ajuste de línea (sin scroll horizontal):

pre {
  white-space: pre-wrap;
  word-wrap: break-word;
}

⚠️ Errores comunes

  • ❌ Usarlo para texto normal (no formateado).
  • ❌ Olvidar escapar caracteres especiales (<, >, &) → rompe el HTML.
  • ❌ No manejar el desbordamiento horizontal → scroll o desborde raro.
  • ❌ Usarlo sin <code> para código fuente (pierde semántica).
  • ❌ Poner espacios o saltos de línea al inicio del contenido (se incluyen).
  • ❌ Usar <pre> para layout (era el patrón antiguo, hoy es mala práctica).
  • ❌ No controlar el ancho → bloques muy anchos en móvil.
  • ❌ Usar <pre> para poemas cuando <blockquote> o <p> con <br> es mejor.
  • ❌ Combinarlo con etiquetas que no respetan el formato (algunos elementos inline sí, otros no).
  • ❌ Olvidar overflow-x: auto para bloques de código largos.

💼 Casos de uso

  • Bloques de código en documentación y blogs técnicos.
  • ASCII art y diagramas de texto.
  • Poemas o letras con formato específico.
  • Tablas de texto alineadas.
  • Salida de programas o logs.
  • Ejemplos de configuración (JSON, YAML, etc.).
  • Documentación de APIs con ejemplos de peticiones.
  • Editoriales de código (code editors embebidos).

🧩 Relación con otros conceptos

  • <code>: marca código inline; se combina con <pre> para bloques.
  • <kbd>: entrada de teclado.
  • <samp>: salida de un programa.
  • <var>: variables matemáticas o de programación.
  • white-space: pre (CSS): equivale al comportamiento de <pre>.
  • white-space: pre-wrap (CSS): conserva espacios y ajusta línea.
  • white-space: pre-line (CSS): colapsa espacios pero respeta saltos.
  • <textarea>: campo editable multilínea (diferente a <pre>).
  • Resaltado de sintaxis: Prism.js, Highlight.js, Shiki.
  • Accesibilidad: lectores de pantalla lo anuncian como "texto preformateado".

🧠 Analogía

<pre> es como una máquina de escribir: cada espacio y cada salto de línea se respeta tal cual lo escribes. En cambio, el HTML normal es como un procesador de texto: colapsa espacios y ajusta el texto al ancho del contenedor.

📝 Notas personales

  • Conserva espacios y saltos: no colapsa como el resto del HTML.
  • Fuente monoespaciada por defecto.
  • Patrón clásico: <pre><code>...</code></pre> para bloques de código.
  • Escapa <, >, & como &lt;, &gt;, &amp;.
  • overflow-x: auto para bloques de código largos.
  • white-space: pre-wrap para ajustar línea sin perder espacios.
  • Cuidado con espacios/saltos al inicio: se incluyen en el contenido.
  • No lo uses para layout: era el patrón antiguo, hoy es mala práctica.
  • Combínalo con <code> para dar semántica de código.
  • Resaltado de sintaxis: añade class="language-xxx" al <code>.
  • En frameworks (React, Vue), <pre> es un componente más.
