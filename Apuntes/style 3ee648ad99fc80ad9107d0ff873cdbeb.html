<style>

📄 <style>

📝 Definición

<style> es el elemento que permite incrustar CSS directamente en un documento HTML.

Su contenido son reglas CSS que se aplican al documento, sin necesidad de un archivo externo.

🧠 ¿Qué es?

Es un elemento de metadatos (metadata content) que se coloca normalmente dentro del <head>, aunque en HTML5 también puede ir dentro del <body> (con scoped en algunos borradores, pero no es estándar).

Su contenido no se muestra: solo afecta al renderizado.

🎯 ¿Para qué sirve?

  • Aplicar estilos sin archivo CSS externo.
  • Prototipar rápidamente.
  • Incluir estilos críticos (critical CSS) para el primer render.
  • Estilos específicos de una página concreta.
  • Variables CSS globales.
  • Evitar peticiones HTTP adicionales (en casos concretos).

⚙️ ¿Cómo funciona?

  1. El navegador lee el contenido del <style> y lo interpreta como CSS.
  1. Aplica las reglas al documento según los selectores.
  1. No se renderiza ni se muestra al usuario.
  1. Si hay varios <style>, se aplican en orden de aparición (cascada).
  1. Bloquea el renderizado hasta que se procesa (por eso va en el <head>).

📝 Sintaxis / Estructura

<style>
  selector {
    propiedad: valor;
  }
</style>

💡 Ejemplos

Estilos básicos:

<head>
  <style>
    body {
      font-family: system-ui, sans-serif;
      background: #f5f5f5;
      color: #222;
    }
    h1 {
      color: #007bff;
    }
  </style>
</head>

Con media para impresión:

<style media="print">
  body {
    font-size: 12pt;
    color: #000;
  }
  nav, footer {
    display: none;
  }
</style>

Con media para responsive:

<style>
  body { font-size: 16px; }
  @media (max-width: 600px) {
    body { font-size: 14px; }
  }
</style>

Variables CSS globales:

<style>
  :root {
    --color-primario: #007bff;
    --color-texto: #333;
  }
  body {
    color: var(--color-texto);
  }
  a {
    color: var(--color-primario);
  }
</style>

Estilos críticos (critical CSS) inline:

<head>
  <style>
    /* Estilos críticos para el primer render */
    header { background: #222; color: #fff; padding: 1rem; }
  </style>
  <link rel="stylesheet" href="estilos.css">
</head>

⚠️ Errores comunes

  • ❌ Poner <style> fuera del <head> o del <body>.
  • ❌ Usar type="text/css" (obsoleto en HTML5).
  • ❌ Incluir HTML dentro de <style> (solo CSS).
  • ❌ Abusar de <style> en lugar de archivos CSS externos.
  • ❌ Olvidar el media en estilos específicos de impresión o responsive.
  • ❌ Usar <!-- --> dentro de <style> (era para navegadores antiguos).
  • ❌ Poner estilos después de que el navegador ya renderizó (parpadeo).
  • ❌ No considerar CSP (Content Security Policy) en producción.
  • ❌ Anidar <style> dentro de otro <style>.

💼 Casos de uso

  • Prototipos rápidos.
  • Critical CSS para el primer render.
  • Estilos específicos de una página concreta.
  • Variables CSS globales.
  • Estilos de impresión (media="print").
  • Emails HTML (donde <style> es la única opción).
  • Widgets o componentes embebidos.
  • Demos y ejemplos en documentación.

🧩 Relación con otros conceptos

  • <link rel="stylesheet">: carga CSS externo (recomendado en producción).
  • CSS inline (style="..."): estilos por elemento (poca especificidad, no reutilizable).
  • @import: importa CSS desde otro archivo (dentro de <style>).
  • @media: consultas de medios dentro del <style>.
  • :root: selector para variables CSS globales.
  • <script>: carga JS (similar pero para scripts).
  • CSP: Content Security Policy (afecta a <style> inline).
  • Render-blocking: <style> bloquea el renderizado.
  • Cascada: orden de aplicación de estilos.

🧠 Analogía

<style> es como las instrucciones de decoración de una casa: no se ven a simple vista, pero determinan cómo se ve todo (colores, distribución, tamaños). Si las escribes en un cuaderno aparte (<link>), la casa se ve igual pero más ordenada. Si las pones directamente en la pared (<style>), es más rápido, pero más difícil de mantener.

📝 Notas personales

  • En producción, prefiere <link> para CSS externo (cacheable, reutilizable).
  • En desarrollo o prototipos, <style> es más rápido.
  • Critical CSS: usa <style> en el <head> para el primer render.
  • type="text/css" ya no es necesario en HTML5.
  • Bloquea el renderizado: ponlo en el <head>.
  • Evita el <!-- -->: era para navegadores antiguos.
  • CSP: en producción, usa nonce o hash si tienes CSP estricta.
  • En emails HTML, <style> es la única opción (los clientes no cargan CSS externo bien).
  • Puedes usar @import dentro, pero es peor rendimiento que <link>.
  • Buena práctica: usa <style> solo para estilos críticos o específicos; el resto, en archivos externos.
