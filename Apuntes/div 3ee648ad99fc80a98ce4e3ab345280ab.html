<div>

📄 <div>

📝 Definición

<div> (del inglés division, "división") es un elemento genérico de bloque en HTML.

No aporta semántica: se usa como contenedor para agrupar y estructurar otros elementos, normalmente con fines de estilo (CSS) o manipulación (JS).

🧠 ¿Qué es?

Es un elemento de bloque sin significado semántico propio.

Es el "comodín" del HTML: sirve para envolver contenido cuando ningún elemento semántico (<section>, <article>, <aside>, etc.) es apropiado.

🎯 ¿Para qué sirve?

  • Agrupar elementos para aplicar estilos CSS.
  • Crear layouts: columnas, grids, flexbox.
  • Envolver contenido para manipularlo con JavaScript.
  • Servir de contenedor cuando no hay un elemento semántico adecuado.
  • Aplicar clases o IDs para selectores.
  • Estructurar sin aportar significado.

⚙️ ¿Cómo funciona?

  1. El navegador lo renderiza como bloque (display: block).
  1. No tiene estilos visuales por defecto (salvo display: block).
  1. Puede contener cualquier elemento de flujo: <p>, <ul>, <img>, otros <div>, etc.
  1. No debe usarse dentro de elementos inline como <p>, <span>, <a>.
  1. Los lectores de pantalla lo ignoran (no aporta semántica).

📝 Sintaxis / Estructura

<div>
  Contenido del contenedor
</div>

💡 Ejemplos

Contenedor para estilos:

<div class="tarjeta">
  <h2>Título</h2>
  <p>Descripción de la tarjeta.</p>
</div>
.tarjeta {
  background: #fff;
  padding: 1.5rem;
  border-radius: 8px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.1);
}

Layout con grid:

<div class="grid">
  <div class="columna">Columna 1</div>
  <div class="columna">Columna 2</div>
  <div class="columna">Columna 3</div>
</div>
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 1rem;
}

Contenedor para JavaScript:

<div id="app"></div>
<script>
  document.getElementById('app').textContent = 'Hola mundo';
</script>

Contenedor genérico en un layout:

<body>
  <div class="contenedor">
    <header>...</header>
    <main>...</main>
    <footer>...</footer>
  </div>
</body>
.contenedor {
  max-width: 1200px;
  margin: 0 auto;
  padding: 0 1rem;
}

Wrapper para modal:

<div class="modal" role="dialog" aria-modal="true">
  <div class="modal-contenido">
    <h2>Confirmar acción</h2>
    <p>¿Estás seguro?</p>
    <button>Aceptar</button>
  </div>
</div>

⚠️ Errores comunes

  • ❌ Usarlo cuando hay un elemento semántico adecuado (<section>, <article>, <nav>, <header>, <footer>, <aside>, <main>).
  • ❌ Anidar <div> dentro de <p> (inválido: <p> solo admite inline).
  • ❌ Usarlo dentro de <span>, <a> u otros elementos inline.
  • ❌ "Divitis": abusar de <div> para todo.
  • ❌ Usarlo como botón o enlace (para eso <button> o <a>).
  • ❌ Usar align="center" (obsoleto, usar CSS).
  • ❌ No aportar role o aria-* cuando sí tiene función semántica.
  • ❌ Usarlo para texto que debería ir en <p> o encabezados.
  • ❌ Anidar <div> innecesariamente (wrappers vacíos).

💼 Casos de uso

  • Contenedores de layout (grid, flexbox).
  • Tarjetas de producto, post, usuario.
  • Modales y diálogos.
  • Wrappers para centrar o limitar ancho.
  • Puntos de montaje para frameworks (React, Vue).
  • Agrupación para JS (eventos, animaciones).
  • Cajas de estilo sin semántica específica.
  • Separadores visuales con CSS.
  • Contenedores de fondo o decoración.

🧩 Relación con otros conceptos

  • <span>: contenedor inline genérico (equivalente a <div> pero inline).
  • <section>: agrupación temática (semántica).
  • <article>: contenido autónomo (semántico).
  • <aside>: contenido secundario (semántico).
  • <header> / <footer>: cabecera y pie (semánticos).
  • <main>: contenido principal (semántico).
  • <nav>: navegación (semántico).
  • CSS: display, flex, grid, padding, margin, background.
  • role / aria-*: para aportar semántica cuando sea necesario.
  • Accesibilidad: los lectores de pantalla ignoran el <div>.

🧠 Analogía

Un <div> es como una caja de cartón sin etiqueta: puedes meter lo que quieras dentro, pero no dice nada sobre su contenido. En cambio, <section> sería una caja etiquetada "capítulo", <article> una etiquetada "artículo", <nav> una etiquetada "menú". Usa <div> solo cuando ninguna etiqueta se ajuste.

📝 Notas personales

  • Último recurso: si hay un elemento semántico adecuado, úsalo.
  • No aporta semántica: los lectores de pantalla lo ignoran.
  • No puede ir dentro de <p>, <span>, <a> u otros inline.
  • Para inline genérico, usa <span>.
  • Para layout, combínalo con display: flex o grid.
  • Evita la "divitis": no anides <div> innecesariamente.
  • Si el <div> tiene función semántica, añade role y aria-*.
  • En CSS, <div> no tiene estilos por defecto (solo display: block).
  • En frameworks (React, Vue), <div> es el contenedor más usado.
  • Pregunta clave: "¿Hay un elemento semántico que describa esto?" → Si sí, úsalo; si no, <div>.
