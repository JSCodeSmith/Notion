<select>

📄 <select>

📝 Definición

<select> es el elemento que crea una lista desplegable de opciones en HTML.

Permite al usuario elegir una o varias opciones de un conjunto predefinido, presentadas como un menú.

🧠 ¿Qué es?

Es un elemento inline-block y semántico que agrupa opciones (<option>) y grupos de opciones (<optgroup>).

Su apariencia nativa varía entre navegadores y sistemas operativos.

🎯 ¿Para qué sirve?

  • Elegir una opción de una lista (país, categoría, talla).
  • Elegir varias opciones (con multiple).
  • Ahorrar espacio en formularios con muchas opciones.
  • Agrupar opciones relacionadas con <optgroup>.
  • Aportar semántica: indica una selección de opciones.
  • Mejorar accesibilidad: los lectores de pantalla lo anuncian como "cuadro combinado" o "lista".

⚙️ ¿Cómo funciona?

  1. El navegador lo renderiza como menú desplegable (o lista, con multiple).
  1. Al hacer clic, se despliegan las <option>.
  1. El usuario elige una (o varias) y el valor se envía con el formulario.
  1. El valor enviado es el value de la <option> seleccionada.
  1. Si una <option> no tiene value, se envía su texto visible.
  1. No es editable: para eso existe <datalist> o <input list>.

📝 Sintaxis / Estructura

<select name="pais" id="pais">
  <option value="">-- Elige un país --</option>
  <option value="es">España</option>
  <option value="mx">México</option>
  <option value="ar">Argentina</option>
</select>

💡 Ejemplos

Select básico:

<label for="pais">País:</label>
<select id="pais" name="pais">
  <option value="">-- Elige un país --</option>
  <option value="es">España</option>
  <option value="mx">México</option>
  <option value="ar">Argentina</option>
</select>

Con opción preseleccionada (selected):

<select name="pais" id="pais">
  <option value="es">España</option>
  <option value="mx" selected>México</option>
  <option value="ar">Argentina</option>
</select>

Con grupos (<optgroup>):

<select name="ciudad" id="ciudad">
  <optgroup label="Europa">
    <option value="mad">Madrid</option>
    <option value="par">París</option>
  </optgroup>
  <optgroup label="América">
    <option value="mex">Ciudad de México</option>
    <option value="bue">Buenos Aires</option>
  </optgroup>
</select>

Con multiple (selección múltiple):

<label for="lenguajes">Lenguajes que conoces:</label>
<select id="lenguajes" name="lenguajes" multiple size="5">
  <option value="html">HTML</option>
  <option value="css">CSS</option>
  <option value="js">JavaScript</option>
  <option value="py">Python</option>
  <option value="go">Go</option>
</select>

Con required y validación:

<form action="/enviar" method="post">
  <label for="talla">Talla:</label>
  <select id="talla" name="talla" required>
    <option value="">-- Selecciona --</option>
    <option value="s">S</option>
    <option value="m">M</option>
    <option value="l">L</option>
  </select>
  <button type="submit">Enviar</button>
</form>

Con opciones deshabilitadas:

<select name="plan" id="plan">
  <option value="basico">Básico</option>
  <option value="pro" disabled>Pro (agotado)</option>
  <option value="premium">Premium</option>
</select>

Con estilos CSS:

<select class="elegante" name="pais" id="pais">
  <option value="es">España</option>
  <option value="mx">México</option>
</select>
select.elegante {
  padding: 0.5rem 1rem;
  border: 1px solid #ccc;
  border-radius: 6px;
  background: #fff;
  font-size: 1rem;
  appearance: none;
  background-image: url("data:image/svg+xml,...");
  background-repeat: no-repeat;
  background-position: right 0.5rem center;
}

⚠️ Errores comunes

  • ❌ Olvidar name → no se envía el valor.
  • ❌ Olvidar label asociado con for → problema de accesibilidad.
  • ❌ Usar <select> cuando el usuario debería poder escribir libremente (mejor <input list> o <datalist>).
  • ❌ No incluir una opción por defecto (- Elige --) cuando es required.
  • ❌ Anidar <option> fuera de un <select> o <optgroup>.
  • ❌ Usar <select> para navegación (mejor <nav> con enlaces).
  • ❌ Depender del estilo nativo: varía mucho entre navegadores.
  • ❌ Usar multiple sin size → solo se ve una opción.
  • ❌ No considerar accesibilidad: los lectores de pantalla anuncian opciones.
  • ❌ Usar <select> gigantes de 100+ opciones → mala experiencia (mejor autocompletado).

💼 Casos de uso

  • Selección de país, ciudad, idioma.
  • Tallas, colores, cantidades.
  • Categorías en filtros de búsqueda.
  • Fechas (día, mes, año).
  • Formularios de checkout.
  • Configuración de perfil.
  • Ordenación de listados.
  • Selección de plan o suscripción.
  • Filtros en tablas o listados.

🧩 Relación con otros conceptos

  • <option>: cada opción dentro del <select>.
  • <optgroup>: agrupa opciones relacionadas.
  • <label>: etiqueta asociada al <select>.
  • <datalist>: sugerencias editables (a diferencia de <select>).
  • <input list>: combina input + datalist.
  • <input type="radio">: alternativa para pocas opciones visibles.
  • <input type="checkbox">: alternativa para selección múltiple visible.
  • multiple: selección múltiple.
  • size: convierte en lista visible.
  • required: validación nativa.
  • CSS: appearance: none para personalizar.
  • Accesibilidad: lectores de pantalla anuncian "cuadro combinado" o "lista".

🧠 Analogía

Un <select> es como un menú de restaurante: ves las opciones desplegadas, eliges una y se sirve. Con multiple, es como un buffet: puedes elegir varias. A diferencia de un <input>, no puedes pedir algo que no esté en el menú.

📝 Notas personales

  • Siempre name en el <select>: sin él, no se envía.
  • Siempre label asociado con for → accesibilidad.
  • <option value=""> como opción por defecto con required.
  • <optgroup> para agrupar opciones relacionadas.
  • multiple + size para selección múltiple visible.
  • No uses <select> si el usuario debe poder escribir libremente → usa <datalist>.
  • required funciona: el navegador no envía si no hay selección válida.
  • appearance: none en CSS para personalizar el aspecto.
  • Cuidado: los estilos nativos varían mucho entre navegadores y SO.
  • No abuses: si hay muchas opciones, considera un autocompletado con <datalist> o JS.
  • En frameworks (React, Vue), usa componentes controlados para gestionar el estado.
